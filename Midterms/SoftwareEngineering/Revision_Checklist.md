# Software Engineering: Revision Checklist

Use a checkbox only when you can explain or draw the item without looking at the notes. This is a study aid, not a prediction of the next exam.

## 1. Software and process

- [ ] Define software using instructions, data structures and documentation.
- [ ] Explain deterioration without physical wear.
- [ ] Explain when a legacy system needs adaptation or replacement.
- [ ] Reproduce quality focus, process, methods and tools.
- [ ] Name the five framework activities and distinguish umbrella activities.
- [ ] Compare linear, iterative, evolutionary and parallel flows.
- [ ] Draw/explain waterfall and its difficulty with changing requirements.
- [ ] Explain prototyping and the danger of shipping an unsuitable prototype.
- [ ] Explain risk-driven spiral development.
- [ ] Name Unified Process phases.

**Notes:** [Software and SE](notes/01_Week1_Software_SoftwareEngineering.md), [Process models](notes/02_Week1_ProcessModels.md).

## 2. Management and planning

- [ ] Explain the four Ps and stakeholder roles.
- [ ] Explain the five leadership practices and team toxicity.
- [ ] List team-structure selection factors.
- [ ] Explain formal/informal communication and W5HH.
- [ ] Distinguish scope, feasibility, size, effort, duration and cost.
- [ ] Calculate effort/cost from size and productivity with correct units.
- [ ] Explain FP adjustment and UCP terms.
- [ ] Explain why independent estimates should be reconciled.
- [ ] Distinguish a dependency network from a Gantt chart.
- [ ] Explain lateness causes, risk investigation, contingency and progress tracking.

**Notes:** [Management](notes/03_Week2_ProjectManagement.md), [Planning](notes/04_Week2_Planning_Estimation_Scheduling.md).

## 3. Agile and practice

- [ ] Explain customer collaboration and the cost of late changes.
- [ ] Distinguish iteration from an increment.
- [ ] Compare Scrum, XP, Kanban and DevOps.
- [ ] Distinguish sprint review from retrospective.
- [ ] Explain architecture and risk decisions in evolving prototypes.
- [ ] Distinguish acceptance testing from regression testing.
- [ ] Give examples of four maintenance types.
- [ ] Explain separation of concerns, abstraction and modularity.
- [ ] Explain why testing cannot guarantee absolute absence of defects.

**Notes:** [Agility](notes/05_Week3_Agility_Process.md), [Recommended process](notes/06_Week3_RecommendedProcess.md), [Practice](notes/07_Week4_PracticePrinciples.md).

## 4. Requirements and diagrams

- [ ] Explain all seven RE tasks.
- [ ] Extract FR/NFR without inventing numerical limits.
- [ ] Identify ambiguities and ask useful elicitation questions.
- [ ] Explain requirement validity, traceability and change management.
- [ ] Explain the purposes of scenario/class/behavior/data/flow models.
- [ ] Identify actors and draw goals inside the correct system boundary.
- [ ] Write a use case with preconditions, main/alternative flows and postconditions.
- [ ] Identify candidate classes, attributes and operations.
- [ ] Make a CRC card and walk through a scenario with it.
- [ ] Draw and label class/state/activity symbols.
- [ ] Distinguish sequence, state, activity and swimlane models.
- [ ] Explain WebApp content/interaction/function/navigation/configuration models.
- [ ] Explain content analysis using information objects and relationships.
- [ ] Explain why the old four-element question needs taxonomy clarification.

**Notes:** [Understanding requirements](notes/08_Week4_UnderstandingRequirements.md), [Modeling](notes/09_Week5_RequirementsModeling.md), [Supplement](notes/14_Supplement_WebApps_UML.md).

## 5. Design and UX

- [ ] Distinguish abstraction, refinement, modularity, hiding and refactoring.
- [ ] Explain high cohesion and low coupling.
- [ ] Explain the modularity/integration-cost tradeoff.
- [ ] Identify data, architecture, interface, component and deployment concerns.
- [ ] Sketch the six architectural styles and explain MVC roles.
- [ ] Explain context, archetypes, quality tradeoffs and architecture reviews.
- [ ] Explain component views and the principles listed in Ch11.
- [ ] Explain both CBSE benefits and risks.
- [ ] Reproduce five UX levels and three golden rules.
- [ ] Distinguish persona, journey map and use case.
- [ ] Explain usability/accessibility and the five design-sprint steps.

**Notes:** [Design](notes/10_Week6_DesignConcepts.md), [Architecture](notes/11_Week6_ArchitecturalDesign.md), [Components](notes/12_Week7_ComponentLevelDesign.md), [UX](notes/13_Week7_UserExperienceDesign.md).

## 6. Timed past-paper practice

- [ ] Attempt [2023](MidtermSamples/Midterm_2023_Solved.md) before reading its answers.
- [ ] Attempt [2024](MidtermSamples/Midterm_2024_Solved.md) before reading its answers.
- [ ] Attempt [2025](MidtermSamples/Midterm_2025_Solved.md) before reading its answers.
- [ ] Check that case FRs cover all roles, not only the highlighted use case.
- [ ] Check that diagram and written scenario agree about payment and completion.
- [ ] Check that error flows can finish/recover and do not claim success on failure.
- [ ] Record questions needing instructor clarification.

All three supplied papers allow 60 minutes. Marks suggest roughly 34 minutes theory / 26 case for 2023-2024 and 36 / 24 for 2025, before reserving reading/checking time. Adjust this study allocation to your own speed.
